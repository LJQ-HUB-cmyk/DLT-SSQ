## 0. 一句话结论

**技术上完全可以接，WorkBuddy 也有完整的变现机制（付费 Skill + 微信提现）。
但"选号神器"这个方向不该做** —— 原因在第 4 节，用数据讲。

## 1. WorkBuddy 开放平台是什么

腾讯出品的全场景 AI 办公工作台，2026-09-02 开放平台上线，首批引入超百家生态伙伴。

**五种开发形态**（选一种或组合）：

| 形态 | 定位 | 适合我们吗 |
|---|---|---|
| **Skill** | 可复用的任务步骤 + 资料 + 脚本 | ✅ **最适合**（已打包） |
| **Expert / Expert Team** | 专业角色 + 工作方法 + 分工 | 🟡 可做"彩票分析师"人格 |
| **Connector** | 对外部服务的授权访问和操作 | 🟡 可接我们的远程 API |
| **Buddy App** | 行业专属工作台（多页面 + 场景胶囊 + 商城） | 🟡 量大，可后期做 |
| **Third-Party App** | 硬件/分享能力接入 | ❌ 不相关 |

**变现机制**（`/docs/monetization`）：
- Onboarding：填信息 → 信息审核 → **微信签协议** → 激活
- 发布付费资产：设是否付费 / **一次性付费** / **月付**
- 管理收入：查看收入 → 更新结算账户 → **微信提现**

服务类别里有 **Sports（体育）** 和 **Tools（工具）**，我们归 Sports + Tools。

## 2. 三种接入方式（都已具备基础）

### 方式 A：本地 MCP（推荐，桌面端 WorkBuddy）

WorkBuddy 桌面端直接调本地进程，**不需要公网部署**。

`~/.workbuddy/mcp.json`（全局）或项目目录下 `.workbuddy/mcp.json`：

```json
{
  "mcpServers": {
    "lottery-lab": {
      "command": "python",
      "args": ["D:\\工作区\\体育彩票预测项目\\scripts\\mcp_server.py"]
    }
  }
}
```

暴露 6 个工具：

| 工具 | 作用 |
|---|---|
| `lottery_expectation` | 期望值 / 返奖率 / 凯利最优 |
| `optimize_dan_tuo` | 预算 → 最优胆拖结构 + 具体号码 |
| `evaluate_dan_tuo` | 具体方案的精确中奖率与期望 |
| `backtest_dan_tuo_real` | 真实历史回测（247 万次判奖） |
| `scan_sports_arb` | 竞彩跨市场套利扫描 |
| `explain_lottery_truth` | 常见迷思的真答案（基于实测） |

自检：`python scripts/mcp_server.py --selftest`

### 方式 B：远程 MCP（给团队 / 别人用）

```bash
python scripts/mcp_server.py --transport streamable-http --port 8765
```

在 WorkBuddy 里添加远程 MCP，填 `https://<你的域名>/mcp`。
需要一台公网可达的机器 + HTTPS 证书。

### 方式 C：Skill 包（上架到 Skill 市场）

已打包：`dist/lottery-lab.zip`（12.2 KB，4 个文件）

```
lottery-lab/
├── SKILL.md              技能定义 (YAML frontmatter + 指令正文)
├── references/
│   ├── truth-and-data.md  每个结论背后的真实实验数据
│   └── metrics.md         指标定义与口径
└── scripts/
    └── lottery_lab.py     瘦客户端 (不依赖 MCP)
```

打包：`python scripts/pack_skill.py`

> ★ zip 内部顶层直接是 `lottery-lab/`，**不要多套一层**，否则平台解析会失败。
> ★ frontmatter 必填字段：`name` `display_name` `display_name_en` `description`
>   `description_zh` `description_en` `version` `author`

## 3. 我们的差异化：把"诚实"做成产品

市面上全是吹"预测大师"的。我们可以反过来做**唯一不说谎的那个**：

| 市面常见 | 我们的做法 |
|---|---|
| "AI 智能选号，命中率提升 80%" | "给你 47.43% 的中奖率，期望净收益 -790 元" |
| 隐藏期望值，只讲中奖率 | **每次都返回期望净收益和凯利 f\*=0** |
| 拿历史 ROI 证明有效 | **同时给随机对照**，揭穿"历史 ROI +63% 只是运气" |
| 卖"内部号" | 明确说冷热号 z=-0.22，与随机无差异 |

**这既是差异化，也是护城河**：
- 用户用了会亏 → 但工具**提前就说了会亏** → 不容易招投诉
- 平台审核 2.4「内容与服务资质」、2.5「推广与营销」时，诚实定位反而是加分项
- 竞彩方向是**真有数学优势**的（ROI +1.3~1.5%），能撑起付费价值

## 4. ⚠️ 商业判断：哪条路真能收钱

### ❌ 路径 A：C 端"选号神器"付费 Skill —— **不建议**

**技术能做，商业上不能做。**

1. **期望必亏**：用户付费后必然亏钱 → 必然退款 + 差评（平台有退款机制）
2. **自相矛盾**：我们的工具会告诉他"期望 -790 元"，然后他付费买这个结论 → 不会有人长期付费
3. **合规风险**：广告法禁止"提高中奖率""必中"类表述；平台 2.5「推广与营销」也管这块
4. **先例已经翻车**：腾讯云开发者社区有个人发过《我用 WorkBuddy 建立一个大乐透彩票模型》，
   做的是"帮开体彩店的朋友做购彩方案推荐"，2854 期回测后结论是
   **"最佳策略居然是随机，长期来看都是亏本的"**，并特意写文警示"千万不能当真"。

> 那个案例跟我们的结论**完全一致**。区别在于：他把它当成了个人项目，
> 我们可以把它做成**有真实价值的 B 端工具**。

### ✅ 路径 B：B 端给彩票店做工具 —— **推荐**

**店的需求是真的**：彩民每天问"今天买什么号"，店员答不上来就流失客源。

我们能提供：
- 基于真实数据的**购彩方案推荐**（结构最优，不是"预测号"）
- 门店**数据看板**（哪个号码池结构在本店客群中中奖率更高）
- 给店员的**话术模板**："我们用真实开奖数据算过，中奖率 47%，期望是亏的，你自己定"

**收费对象是店（B 端），不是赌徒（C 端）** —— 店的付费意愿来自"留住彩民"和"省时间"。

⚠️ 边界：工具**不能变成"诱导彩民多买"**的帮凶（涉嫌帮助赌博），
也不该按"帮店多卖彩票"分成。定位应是**数据服务 + 理性提示**。

### ✅ 路径 C：竞彩跨市场套利工具 —— **唯一有真数学优势**

| 项 | 值 |
|---|---|
| 跨公司套利 ROI | **+1.3% ~ +1.5%**（36,535 场实测，跨 5 大联赛全正） |
| 中国竞彩抽水 | 12.91% → **参与次数 0** |
| 客群 | 小众但付费能力强（懂赔率的人） |
| 门槛 | 需要付费境外赔率源 + 多账户 |

### ✅ 路径 D：平台分成（最省事的变现）

发布 Skill → 用户安装/付费 → **平台分成 → 微信提现**。
我们不直接收款，**合规压力最小**。

## 5. ⚠️ 合规红线（硬性，不能碰）

| # | 红线 | 说明 |
|---|---|---|
| 1 | **不得代售彩票** | 彩票是**国家专营**，销售须持《彩票代销证》。我们**绝不接触注款、不代下单、不代付** |
| 2 | **不得承诺/暗示中奖** | 广告法 + 平台 2.5 条款。禁用"必中""稳赚""提高中奖率""内部号" |
| 3 | **不得代购代付** | 涉赌资金通道，风险极高 |
| 4 | **不得面向未成年人** | 需年龄提示与限制 |
| 5 | **必须显著标注期望值** | 这是我们的差异化，也是合规护城河 |
| 6 | **数据要标来源与时效** | 每个数字标注期数、样本、来源 API |

## 7. 我的建议

**先做路径 B（B 端给店做工具）+ 路径 D（平台分成），不做 C 端选号神器。**

理由很简单：**卖给赌徒一个必然让他亏钱的东西，做不出长期生意；卖给店家一个帮他留住客人的工具，可以。**

而且我们的工具天然适合 B 端 —— 因为它输出的不是"选号建议"，
是"结构建议 + 真实数据 + 期望值告知"，这对店家来说恰恰是**差异化的话术**：
别人都在吹能中奖，只有我们敢说真话，彩民反而更信。
